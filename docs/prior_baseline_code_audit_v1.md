## Verified behavior, not a conclusion about published model provenance

The pinned `src/training/MVEUDA/train_utils.py` has one `train_loop_mve`
definition. It computes the MMD term inside a no-gradient context and
optimizes beta-NLL alone; its `da_weight` argument does not affect that loss.
The corresponding RunA notebook imports this function, passes a constant
weight 1.4 and beta .5, and trains for 150 epochs. It also saves checkpoints
selected using target-validation R2/MVE/NLL as well as a source-selected
checkpoint. This must be accounted for when matching information access.

An isolated CPU fixture executed only the reviewed AST definitions of
`MMD_loss`, `loss_bnll` and `train_loop_mve`, redirecting the function's CUDA
tensor calls to CPU. With identical initial weights/source/target batches,
changing DA weight from zero to 1.4 produced **exactly zero maximum parameter
difference after one optimizer step**. This verifies the inspected utility's
behavior. It does not establish which source revision produced the published
results or saved model artifacts. Target forwards can still change BatchNorm
statistics in the author's network, so this is not equivalent to proving that
target images have no effect whatsoever.

The source uses summed Gaussian kernels with five geometrically spaced
bandwidths estimated from detached pooled pairwise squared distances. Our
existing fixed-bandwidth kernel average is a different choice. The new
`src/ml/adaptive_mmd_v1.py` implements the inspected kernel construction with
active feature gradients. On an equal-batch fixture, its loss differed from
the author implementation by only **2.98e-7**, and the feature-gradient norm
was **0.3060**. These are implementation checks, not lens accuracy results.
An explicit epsilon guard for collapsed features is a documented deviation;
the inspected original divides by zero in that case. Unequal source/target
batch sizes use separate kernel-block means in the port.

## Consequences for the benchmark

Keep exact pinned-code reproduction separate from a functioning implementation
of the paper's intended MMD method. Do not use a disabled adaptation gradient
as the primary baseline and then claim a scientific improvement. The shared
benchmark will use an active, tuned MMD term and source-only checkpoint
selection. Its single-band backbone, native input size, regression objective,
source data size and target-access restrictions must be listed as port
deviations. An exact multiband paper reproduction remains incomplete.

The main unseen-family experiment withholds Moffat images from all arms,
including target adaptation. It measures generalization beyond the available
adaptation distribution. It does not establish superiority over adaptation
given representative unlabeled Moffat target images. Before making that
stronger claim, add a separately labeled target-aware comparison using fresh,
parent-disjoint unlabeled Moffat adaptation images, equal target exposure
budgets across adaptation arms, and no final images or labels in tuning.

Do not contact authors automatically. If later correspondence is authorized,
ask which revision generated the released models and whether the inspected
utility is intended for the published UDA experiment. Until clarified, describe
this as a pinned-code reproducibility discrepancy, not a paper retraction,
invalidated result or evidence that our method is better.
